# StackF765 flight controller renders

Interactive 3D renders of the StackF765 flight controller, published with GitHub Pages:

- Drone view: https://peterjburke.github.io/dronerenders-claude/fc/
- Board view: https://peterjburke.github.io/dronerenders-claude/fc/board.html
- Comparison with the Matek F405-WMO: `fc/compare-upper.html`, `fc/compare-lower.html`

This site holds renders only. The design files and documentation are in
[PeterJBurke/stackf765](https://github.com/PeterJBurke/stackf765).

It is **separate from [PeterJBurke/dronerenders](https://github.com/PeterJBurke/dronerenders)**.
The pages are modelled on that site's `fc/` viewer (same layout, controls and camera presets) but
nothing here reads from, writes to or depends on that repository; every asset is in this one.

Status of the board shown: design verified by rule checks; no hardware built yet.

## What is in here

| Path | What it is |
|---|---|
| `fc/index.html` | Drone view: the stack in a MOD-L 4-inch HD Cargo frame |
| `fc/board.html` | Board view: stack, single boards, orthographic pin layout |
| `fc/compare-upper.html`, `fc/compare-lower.html` | Same-scale comparison with the Matek F405-WMO reference model |
| `fc/models/*.glb` | The three board models, exported by KiCad from the design |
| `fc/assets/stackf765-loader.js` | Loads the GLB files, places them, applies display colours |
| `fc/assets/pin-data.js` | Pin table, generated by `tools/make-pin-data.py` |
| `tools/adapt-reference-pages.py` | Record of how the pages were derived from the dronerenders `fc/` pages: every text and code substitution, nothing else changed. Needs a local clone of that repo; not needed to refresh models |
| `CREDITS.txt` | Sources and licences (frame, coin, Matek reference, three.js) |

## Refreshing the models

After the design changes, with a StackF765 checkout that has freshly exported
`docs/boards/{lower,upper,service}/*.glb`:

```sh
./sync-models.sh /path/to/stackf765     # default path: /root/fcclaude
git add -A && git commit -m "Refresh board models" && git push
```

The script copies the three GLB files into `fc/models/` and regenerates the pin table from
`gen/upper.py` and `gen/lower.py`. GitHub Pages republishes a minute or two after the push.

## Viewing locally

```sh
python3 -m http.server 8000      # then open http://localhost:8000/fc/
```

The pages load their models with `fetch`, so they need a web server; opening the files directly
from disk does not work.
